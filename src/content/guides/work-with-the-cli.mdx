Install the CLI globally so you can type `thally` directly:

```bash
npm install --global @thallylabs/cli
```

Without a global install you can still run any command through npx, for example
`npx --yes --package=@thallylabs/cli@latest thally dev`. The project's
`npm run check` script wraps `thally check` for you. `npm run dev` starts the
same local server but runs `next dev` directly, so it does not print the agent
endpoint URLs and `claude mcp add` command that `thally dev` provides.

## The daily loop

<Steps>
  <Step title="Run the site locally">
    ```bash
    thally dev
    ```

    Serves the site with search, agent endpoints, and the API playground
    live, so what you review locally is what readers get. Once it is ready,
    it prints the local `/llms.txt` and `/api/mcp` URLs and a
    `claude mcp add` command for connecting Claude Code.
  </Step>
  <Step title="Add a page">
    ```bash
    thally new deploy-guide --title "Deploy your first project"
    ```

    Creates the page and registers it in `docs.json` in one step.
  </Step>
  <Step title="Check before you push">
    ```bash
    thally check
    ```

    Lints content, verifies links and navigation, and scores how well the
    site answers questions for AI tools. This is the same Agent Readiness
    score the Cloud dashboard shows. Add `--ci` in pipelines.
  </Step>
</Steps>

## Let the CLI write the first draft

`thally agent` turns a change you describe, or a merged pull request, into a
reviewed docs update:

```bash
thally agent "document the new webhook retry behavior" --pr
```

Wire it to your product repositories with `thally track add <owner/repo>` and
merged product PRs open docs PRs on their own.

## Everything else

```bash
thally --help
```

Translation (`thally translate`), migration (`thally migrate`), deployment
(`thally deploy`), and starter updates (`thally starter update`) each print
their own usage with `--help`.
